# OMSI Map Editor

A Windows desktop editor foundation for creating and maintaining OMSI 2 maps. It currently contains the Unity project scaffold, a UI Toolkit shell, and a read-only Grundorf importer for map overview data. Map editing and full OMSI format support are not implemented yet.

## Requirements

- Unity 6.6, editor version `6000.6.6f1` (Windows 64-bit)
- Unity Hub to install/manage the editor
- Unity Universal Render Pipeline package `17.6.0` (pinned in `Packages/manifest.json`)
- Git 2.x
- Visual Studio with Unity workload or JetBrains Rider is recommended. Visual Studio Build Tools alone provide compilers but no IDE.

## Open the project

1. Open the installed Unity `6000.6.6f1` through Unity Hub.
2. In Unity Hub, choose **Add > Add project from disk** and select this repository root, the folder containing `Assets`, `Packages`, and `ProjectSettings`.
3. Let Unity resolve packages and finish the first import. The editor setup hook creates `Assets/_Project/Settings/EditorPipeline.asset` and assigns URP to graphics and quality settings.
4. Open `Assets/_Project/Scenes/EditorStartup.unity` and press Play to view the initial shell.
5. For a standalone player, use **File > Build Profiles**, select Windows, confirm the startup scene is included, and build. A successful Windows player build was generated in `Builds/Windows/`.

To inspect an existing OMSI map, use **File > Open OMSI map...** or the central **Open OMSI map...** button in the Windows app and select the installation's `global.cfg`. The app reads source files directly from the external OMSI installation and displays tile and record summaries. The Unity Editor also provides **OMSI Map Editor > Import > Read OMSI Map...**. OMSI game content itself must not be bundled with the player. The build helper collects the actual player dependencies and rejects any that are byte-identical to a file in the remembered installation. The earlier reviewed-asset allowlist has been removed for now. See [GrundorfFormatInventory.md](Documentation/GrundorfFormatInventory.md).

Unity writes generated project settings and `Packages/packages-lock.json` during import. The resolved package lock is checked into this repository so collaborators use the same transitive package versions.

## Project structure

- `Assets/_Project/Scripts/` holds first-party C# modules. Each module has an assembly definition.
- `Assets/_Project/UI/` contains the UI Toolkit shell and its stylesheet.
- `Assets/_Project/Scenes/` contains the startup scene.
- `Assets/_Project/Settings/` stores project-owned rendering settings; `Settings/Resources/editor-settings.json` holds application defaults read by the editor setup and the player.
- `Assets/_Project/Tests/Editor/` contains EditMode tests for the OMSI reader, geometry, and settings.
- `Packages/manifest.json` pins direct Unity packages.
- `Documentation/` records architecture, setup, decisions, and roadmap.

## Current status

Unity `6000.6.6f1` imported the project, resolved URP `17.6.0`, compiled the project assemblies, and produced a Windows player. The Grundorf importer reads 19 tiles and plots object and spline placements in the Unity Editor; the standalone app can save and reopen a versioned `.omproj` file that points to an external `global.cfg`, select tiles in the map view or project browser, inspect their object, spline, and terrain summaries, fit the map to the viewport, and zoom. **Tools** checks the loaded map: it lists import warnings and verifies that connected splines meet. Maps with `[worldcoordinates]`, such as Berlin-Spandau, use their wider 371.9 m tile grid. Full model rendering and map editing remain early scaffolding. See the setup guide and [Grundorf format inventory](Documentation/GrundorfFormatInventory.md) for validation details and the player content boundary. Timetable (`TTData`) and chrono formats are documented in [TimetableChronoInventory.md](Documentation/TimetableChronoInventory.md); they are not imported yet. The complete tile record and `global.cfg` layouts are documented in [TileRecordInventory.md](Documentation/TileRecordInventory.md). Map files are read through a lossless model that reproduces every text file of the installed maps byte for byte; **OMSI Map Editor > Import > Verify Lossless Round Trip...** checks a map folder without writing anything. Typed record views and an ID allocator build on this model.

To edit a map, open it and choose **File > Save map project as...**. The project gets a workspace folder next to the `.omproj` file that holds only edited files; the original map is never changed. The map view shows the whole map from above: the mouse wheel zooms, dragging with the right or middle button pans. Select an object by clicking it on the map or in the inspector list. With a project, the tool bar at the bottom picks what dragging does: **Drag** (Q) selects objects and drags them freely, **Move** (W) adds axis arrows to move the selection exactly east or north and, in 3D, up (Shift moves in whole metres), **Rotate** (E) shows the round handle to turn the selected object (Shift snaps to 15°); **Delete** (Del) and **Objects** (3) delete and place. You can also type values and choose **Apply**. Ctrl+Z and Ctrl+Y undo and redo. The ground is drawn with the map's ground textures, such as grass and cobblestones, roads, sidewalks and tracks with the textures of their spline profiles, and objects with their models and textures standing on the terrain, including objects attached to other objects and rows of lamps, posts and signs along splines, with see-through glass, all read from your OMSI installation; **3D** in the map controls shows the map in perspective on its terrain: the right mouse button turns the view, the middle one moves it and the wheel zooms. With a project, click an object in 3D to select it, drag it to move it over the ground, and drag one of the rings around it to turn it: green for heading, red for pitch, blue for bank (Shift snaps to 15°). The inspector also edits pitch and bank. Crossings and other objects that join splines keep their pitch and bank and show only the green ring. The other tools work in 3D as from above: Ctrl+click and Ctrl+drag select several objects, Del deletes, the object library places on the ground under the pointer, where the object's model already stands as a preview, and **Fit map**, the zoom buttons and **Center selection** move the camera. Objects without a model show a dot, the selected tile its border on the ground. Textures stay on in 3D; the choice made from above returns when 3D is switched off. **Textures** switches between textures and plain tiles; with textures, spline lines are drawn thin and objects that show their model have no marker or outline, while selecting and dragging work as before. Once zoomed in, objects show their footprint: buildings and other objects in grey-blue, trees in green. The outlines are computed in the background from the `.sco` files and meshes of your OMSI installation; see [SceneryObjectInventory.md](Documentation/SceneryObjectInventory.md). To add an object, choose **Objects** (3) in the tool bar or **Edit > Place object...**: the object library opens above the tool bar with the tabs **Library** (the `Sceneryobjects` folders of your installation), **In map** (objects this map uses, with counts) and **Favorites** (objects you starred), and a search across them. **Hide DLC objects** leaves out objects of paid add-ons, so freeware maps need only the base game and freeware; the editor tells them apart by Steam's file lists, and objects outside any Steam package, such as your own or freeware, stay visible. **In map** and **Tools** name DLC objects the map uses. Click an object and click into the map; the library stays open for the next one. Shift+click keeps placing, R turns the preview, Esc stops placing and a second Esc closes the library. **Del** or **Delete object** in the inspector removes the selected object; when timetables, entry points, chrono patches or other objects still refer to it, nothing is deleted and the status bar names the references. Placing and deleting can be undone like any other edit. Ctrl+click adds objects to the selection or removes them, and Ctrl+drag on empty space selects every object in a box; dragging one selected object moves all of them, and Del deletes them as one undoable step. An object moved over a tile border moves into that tile with its rules and ID, unless an entry point, a chrono patch, an attached object or a variable parent ties it to its tile; then it stays in its tile, as OMSI allows. **Revert tile edits** discards the edits of the selected tile. **File > Export to OMSI...** writes the original map plus your edits as a separate map folder next to the original, for example `Grundorf (Mapforge)`, with its own name in OMSI.
