# OMSI Map Editor

A Windows desktop editor for maintaining OMSI 2 maps, in development. It reads maps straight from your OMSI installation and shows them from above and in 3D with their ground, roads and objects. In a project you can move, turn, tilt, place and delete scenery objects, also in 3D, with undo, and export the result as a separate map that OMSI loads. Splines, terrain and timetables cannot be edited yet; see the [roadmap](Documentation/Roadmap.md).

## Requirements

- Unity 6.6, editor version `6000.6.6f1` (Windows 64-bit)
- Unity Hub to install/manage the editor
- Unity Universal Render Pipeline package `17.6.0` (pinned in `Packages/manifest.json`)
- Git 2.x
- Visual Studio with Unity workload or JetBrains Rider is recommended. Visual Studio Build Tools alone provide compilers but no IDE.

## Open the project

1. Open the installed Unity `6000.6.6f1` through Unity Hub.
2. In Unity Hub, choose **Add > Add project from disk** and select this repository root, the folder containing `Assets`, `Packages`, and `ProjectSettings`.
3. Let Unity resolve packages and finish the first import. The editor setup hook creates `Assets/_Project/Settings/EditorPipeline.asset` and assigns URP to graphics and quality settings.
4. Open `Assets/_Project/Scenes/EditorStartup.unity` and press Play to view the initial shell.
5. For a standalone player, use **File > Build Profiles**, select Windows, confirm the startup scene is included, and build. A successful Windows player build was generated in `Builds/Windows/`.

The app starts with a welcome screen: **Open project** continues a Mapforge project, **Open OMSI map** opens a map of your installation by its `global.cfg`, and the projects and maps you opened last are one click away. **New map** creates an empty map with one tile on flat ground next to a map of your installation that serves as template: AI lists, drivers, parked cars, holidays and the settings of its `global.cfg` such as ground textures and seasons are taken over, its tiles, timetables and entry points are not. The new tile gets an entry point named "Start" on an entry point object in its middle; OMSI crashes while loading a map without one. Then choose where to save the project of the new map, and it opens for editing. The same commands are in the **File** menu. The app reads source files directly from the external OMSI installation and displays tile and record summaries. The Unity Editor also provides **OMSI Map Editor > Import > Read OMSI Map...**. OMSI game content itself must not be bundled with the player. The build helper collects the actual player dependencies and rejects any that are byte-identical to a file in the remembered installation. The earlier reviewed-asset allowlist has been removed for now. See [GrundorfFormatInventory.md](Documentation/GrundorfFormatInventory.md).

Unity writes generated project settings and `Packages/packages-lock.json` during import. The resolved package lock is checked into this repository so collaborators use the same transitive package versions.

## Project structure

- `Assets/_Project/Scripts/` holds first-party C# modules. Each module has an assembly definition.
- `Assets/_Project/UI/` contains the UI Toolkit shell, its stylesheet with the design tokens, and the Inter font.
- `Assets/_Project/Scenes/` contains the startup scene.
- `Assets/_Project/Settings/` stores project-owned rendering settings; `Settings/Resources/editor-settings.json` holds application defaults read by the editor setup and the player.
- `Assets/_Project/Tests/Editor/` contains EditMode tests for the OMSI file model, reader, editing, geometry, content origins and settings.
- `Packages/manifest.json` pins direct Unity packages.
- `Documentation/` records architecture, setup, decisions, roadmap, the corporate design and the OMSI format findings.

## Current status

Unity `6000.6.6f1` imported the project, resolved URP `17.6.0`, compiled the project assemblies, and produced a Windows player. The Grundorf importer reads 19 tiles and plots object and spline placements in the Unity Editor; the standalone app can save and reopen a versioned `.omproj` file that points to an external `global.cfg`, select tiles in the map view or project browser, inspect their object, spline, and terrain summaries, fit the map to the viewport, and zoom. **Tools** checks the loaded map in the background and shows a report: import warnings, spline connections, map-wide unique IDs and the ID counter, entry points on their object, attached objects and rows along splines on existing parents, variable parents, object and spline files missing from the installation, the connection points of junction objects, the timetable and the chrono variants, and DLC objects. Each topic says OK, Note or Problem, lists its findings and can jump to the tile worth looking at; **Copy report** puts the whole report on the clipboard. Maps with `[worldcoordinates]`, such as Berlin-Spandau, consist of Web Mercator tiles; the editor draws them with the edge of their middle row, 371.9 m for Berlin-Spandau, checks connected splines in the exact tile geometry and shows the latitude and longitude of the selected tile. Full model rendering and map editing remain early scaffolding. See the setup guide and [Grundorf format inventory](Documentation/GrundorfFormatInventory.md) for validation details and the player content boundary. Timetable (`TTData`) and chrono formats are documented in [TimetableChronoInventory.md](Documentation/TimetableChronoInventory.md); the editor reads both without changing them. **Routes** in the map controls shows the bus stops and the routes of the timetable lines from above, on the lane each trip drives over roads and crossings; zoomed in, the stops show their names. **Lines** in the project browser lists the lines with their stops and daily trips; click one to highlight it, click it again to show all lines alike. Routes follow moved stops and crossings. Maps with chrono variants, such as road works or timetable changes that apply from a date, show a **Chrono** section in the project browser: enter a date and choose **Show**, or click a variant to see its first day, and the map shows the objects, splines and lines OMSI uses on that day. This view is read-only; **Base map** returns to the map you edit. The complete tile record and `global.cfg` layouts are documented in [TileRecordInventory.md](Documentation/TileRecordInventory.md). Map files are read through a lossless model that reproduces every text file of the installed maps byte for byte; **OMSI Map Editor > Import > Verify Lossless Round Trip...** checks a map folder without writing anything. Typed record views and an ID allocator build on this model.

To edit a map, open it and choose **File > Save map project as...**. The project gets a workspace folder next to the `.omproj` file that holds only edited files; the original map is never changed. The map view shows the whole map from above: the mouse wheel zooms, dragging with the right or middle button pans. Select an object by clicking it on the map or in the inspector list. With a project, the tool bar at the bottom picks what dragging does: **Drag** (Q) selects objects and drags them freely, **Move** (W) adds axis arrows to move the selection exactly east or north and, in 3D, up (Shift moves in whole metres), **Rotate** (E) shows the round handle to turn the selected object (Shift snaps to 15°); **Delete** (Del) and **Objects** (3) delete and place. You can also type values and choose **Apply**. Ctrl+Z and Ctrl+Y undo and redo. The ground is drawn with the map's ground textures, such as grass and cobblestones, roads, sidewalks and tracks with the textures of their spline profiles, and objects with their models and textures standing on the terrain, including objects attached to other objects and rows of lamps, posts and signs along splines, with see-through glass, all read from your OMSI installation; the terrain is cut away where OMSI cuts it, under crossings and along rail cuttings, and in 3D upright parts of splines such as walls, kerb faces and fences stand on the ground. Overhead lines, catenary and cross spans appear from above as dashed lines, fences and walls as thin grey lines; **3D** in the map controls shows the map in perspective on its terrain: the right mouse button turns the view, the middle one moves it and the wheel zooms. With a project, click an object in 3D to select it, drag it to move it over the ground, and drag one of the rings around it to turn it: green for heading, red for pitch, blue for bank (Shift snaps to 15°). The inspector also edits pitch and bank. Crossings and other objects that join splines keep their pitch and bank and show only the green ring. The other tools work in 3D as from above: Ctrl+click and Ctrl+drag select several objects, Del deletes, the object library places on the ground under the pointer, where the object's model already stands as a preview, and **Fit map**, the zoom buttons and **Center selection** move the camera. Objects without a model show a dot, the selected tile its border on the ground. Textures stay on in 3D; the choice made from above returns when 3D is switched off. **Textures** switches between textures and plain tiles; with textures, spline lines are drawn thin and objects that show their model have no marker or outline, while selecting and dragging work as before. Without textures the map draws splines in orange, objects in blue, trees in green, the selected tile with a gold border and the selection in red, in the colours of the interface. Once zoomed in, objects show their footprint: buildings and other objects in blue, trees in green. The outlines are computed in the background from the `.sco` files and meshes of your OMSI installation; see [SceneryObjectInventory.md](Documentation/SceneryObjectInventory.md). To add an object, choose **Objects** (3) in the tool bar or **Edit > Place object...**: the object library opens above the tool bar with the tabs **Library** (the `Sceneryobjects` folders of your installation), **Groups** (the groups the object files list, such as Buildings or Trees, largest first), **In map** (objects this map uses, with counts) and **Favorites** (objects you starred), and a search across them. Where the map editor nEditor has run on your installation, rows show the preview images it left in `Sceneryobjects\nEditorThumbnails`. **Hide DLC objects** leaves out objects of paid add-ons, so freeware maps need only the base game and freeware; the editor tells them apart by Steam's file lists, and objects outside any Steam package, such as your own or freeware, stay visible. Add-ons bought outside Steam look like freeware to Steam; mark their folder as DLC with the tag button next to it in **Library**, and the editor treats it like a Steam DLC from then on, for every map. Folders that hold only base game objects have no tag button, since every player has them. **In map** and **Tools** name DLC objects the map uses. Click an object and click into the map; the library stays open for the next one. Junctions and other objects whose height OMSI takes as absolute are placed at the height of the terrain under the pointer. Shift+click keeps placing, R turns the preview, Esc stops placing and a second Esc closes the library. **Del** or **Delete object** in the inspector removes the selected object; when timetables, entry points, chrono patches or other objects still refer to it, nothing is deleted and the status bar names the references. Placing and deleting can be undone like any other edit. **Road** (R) in the tool bar builds roads as OMSI splines, from above or in 3D on the ground under the pointer: pick a spline profile in the road panel (those the map uses come first), click where the road starts, on a free spline end to continue that road, and click for each further point; each part leaves tangentially from the last and bends in a circular arc. Esc ends the road, a second Esc leaves the tool. **Follow terrain** puts the road on the ground every 25 m or less; **Smooth** follows the ground averaged over 100 m with a gradient that changes steadily, also where it continues another road; **Manual height** runs it evenly to the end height you enter (with **Fit terrain** off for bridges). The panel shows length, gradient and end height of the road under the pointer and warns about gradients steeper than 10 %, curves tighter than half the road's width and stretches below or high above the ground; a road that must leave and arrive in a given direction, such as from one free end to another, gets two arcs that meet without a kink; with **Fit terrain to the road**, on by default, the ground under the road and for at least one diagonal of the terrain grid beside it (about 7 m) is laid just below kerb height and cut back or banked up beyond with slopes of 1:1.5, so it no longer pokes through the road. As in OMSI, the ground is cut away under the strips of such roads; a grass verge without a strip keeps its ground. **Edit > Fit terrain to built roads again** fits the ground anew along every road built in the editor. The original terrain stays in the original map; deleting the road or undoing it brings the ground back, and **Fit terrain to this road** in the inspector switches it on or off later for a whole road built in the editor. Like OMSI's own editor, the editor marks such roads with `[spline_terrain_align_2]`. Click a spline to select it: square handles at its ends move that end when dragged, as in MoveIt for Cities: Skylines. The spline and the one joined there keep their other ends and their bends, and a kink this leaves is reported; hold Alt to keep the joint free of kinks instead. The round handle in the middle bends the spline through the pointer, and Alt runs it straight. Esc cancels the drag. Junction objects name their connection points as `[splinehelper]` in their `.sco` file: select one to see its points as diamonds on the map and, in the inspector, whether each is connected, needs review (a spline end slightly off in position, height or heading), invalid or unconnected. The road tool snaps to free connection points as to free spline ends and starts or ends the road there with the point's position, heading and height, as OMSI maps join them, without an ID; a road with a free start is planned from the end it joins, so it arrives without a kink. The diamonds follow a junction while you drag or turn it. With **Fit terrain to the road**, the ground beyond a road end on a junction stays as it is, and a junction placed in the editor that such a road joins gets its ground fitted too: just below its carriageway under it, at its kerbs beside it and sloped beyond, anew whenever it moves. Press Del to delete the selected spline; the roads joined to it get an open end, and splines with objects along them or named by timetables stay. Building and deleting roads can be undone. Ctrl+click adds objects to the selection or removes them, and Ctrl+drag on empty space selects every object in a box; dragging one selected object moves all of them, and Del deletes them as one undoable step. An object moved over a tile border moves into that tile with its rules and ID, unless an entry point, a chrono patch, an attached object or a variable parent ties it to its tile; then it stays in its tile, as OMSI allows. **Revert tile edits** discards the edits of the selected tile. **File > Export to OMSI...** writes the original map plus your edits as a separate map folder next to the original, for example `Grundorf (Mapforge)`, with its own name in OMSI.
